# v1.4.9 P4-B-D2 Full Execution 集成验收

本阶段统一完成真实链路接入、故障回退与闭环验证，不再按小模块单独推进。代码基线为 `coding-man-wang/fe-agent` 的 `main@2f6746848accaed764f3f541ff9f80ae33a78b98`。

## 当前落地范围

已接入真实 Full Execution 的 **Guarded Context Preview**。生产 Active 关闭，Coding Agent 始终消费原始 Baseline Bundle。`candidate_valid` 仅表示候选重建校验通过，绝不表示候选已交给模型，更不表示真实 Active A/B 已验收。

新增 `--context-guarded-preview`，复用 D2-A 准入检查、D1 Observer、D2-B Preview 和 C1 Consumer Trial。仅 `CASE-006 / TASK-002`、批准 Revision 与已通过 Canary 匹配时运行候选观察；后续任务使用各自当前 Revision 的 Baseline，不能继承 TASK-002 的实验资格。

```text
已有 Prepared Input + D2-A Preflight
  -> 当前任务 committed snapshot / 一次 Retrieval / Fresh Change Surface
  -> 共用最终构建器：Resolved Context -> Obligation Evidence -> Verification Strategy
  -> 完整输入快照 -> D1 -> D2-B -> C1 -> 审计 -> 最终快照复核
  -> candidate_valid 或安全 fallback：原 Baseline -> Coding / Patch / Verification / Completion
  -> blocked：在 Coding Agent 调用前终止当前任务
```

Baseline 和 C1 重建共同使用 `_build_final_execution_context`。候选重建固定本次 Surface、Index、Task Plan，复用 Selection，不重新 Retrieval、不重新求解 Surface。原有 Scope Guard、Obligation Gate、Verification Strategy Guard 和 Completion Gate 按原流程执行。

## 回退规则

| 条件 | 处理 |
| --- | --- |
| Preflight 拒绝、冲突参数、没有既有通过的 Prepared Input | CLI 退出，不启动该 Full Execution |
| 非白名单任务或不同 Revision | 不运行候选观察，记录 fallback，使用有效 Baseline |
| 无有效删除、必要证据被建议删除、重建元数据/内容不一致 | 候选拒绝；最终快照有效才可使用 Baseline |
| Observer 超时/异常、候选构建异常、审计写入失败 | 最终快照有效则 fallback；报告保留失败原因 |
| 源码、Revision、Selection、Bundle、Surface 或 Obligation 清单变化 | blocked；不能使用旧 Baseline 继续 |
| 已声明的 Obligation Evidence 不在 Baseline | blocked |
| 消息准备后 Bundle 或 committed snapshot 变化 | blocked；更新任务报告并尝试追加阻断审计 |

快照检查覆盖 Selection、最终 Context、Surface/Strategy/Obligation 文件及尚未创建的目标；实际 Git HEAD 和整个 committed worktree 的 tracked/untracked 状态也要保持干净，以覆盖 Enricher 扫描的同目录文件。审计失败路径也执行快照复核。审计只保存路径、字符数、状态与摘要，不保存源码或 Prompt。

禁用 `--context-guarded-preview` 即恢复普通执行入口；无需变更生产配置。源码变化属于阻断条件，不能以“关闭 Preview 后继续消费旧上下文”作为回退；应从正确 Revision 重新开始执行。

## 同一阶段的最终验收条件

Preview 接入和测试通过后，仍需完成隔离 Active A/B 才能关闭整个 D2 阶段。当前交付没有 Active Full Execution 开关，不可通过改动 Preflight 的布尔字段将 Preview 升级为 Active。

隔离实验实现必须复用同一套候选校验，在所有校验和持久化审计成功后，才允许单次向 TASK-002 返回候选 Bundle；必须在消费前重新绑定实际 Case、Task、Revision、Canary、Selection、完整构建输入与最终源码。其他任务继续 Baseline。必要证据门禁还需区分“允许新建但当前不存在的目标”和“已存在却在 Baseline 中缺失的必需证据”，不能仅使用集合交集证明证据完整。

A/B 使用相同 Case、Prepared Input、初始 Revision、模型参数和验证命令，分别创建 run ID 与隔离工作区；不复用上一轮运行的提交状态。记录至少以下项目：

| 指标 | 验收条件 |
| --- | --- |
| Context | 删除文件与批准建议完全一致，保留内容/符号/元数据一致，必要证据覆盖不降低 |
| 功能与修改范围 | Baseline 与 Active 均通过原评估和 Hidden Acceptance，禁止文件命中为 0 |
| 安全门禁 | Snapshot、Scope、Obligation、Strategy、Completion 全通过 |
| 实际开销 | 从模型响应补充 Prompt/Completion/总 Token 与调用次数；未提供 usage 时标记 unavailable |
| 优化效果 | 文件/字符与真实 Token 分开报告；候选无效果或 fallback 不能记为优化成功 |
| 故障注入 | 源码变更/必要证据缺失阻断；候选拒绝/审计不可用在有效 Baseline 上回退 |

任一安全或功能指标退化即拒绝实验结果；不得用 Token 节省抵消。完整 A/B 通过也不会自动启用生产 Active。
